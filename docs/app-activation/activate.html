Wolf Factory Automation — activation

Four steps, about five minutes. Everything below is either a link or a value you copy; nothing here needs judgement.

Both accounts are personal accounts, not organizations. So every link on this page is a personal-account link. The organization URLs used earlier did not apply to either account.

What this creates

AccountTypeRepositoryRole
donraposo1-source User donraposo1-source/project-wolf private Factory (source, dispatch, checks)
insidethemarginmedia-cpu User insidethemarginmedia-cpu/wolf-factory-home public bridge (this repository)

The App is installed once per account, restricted to these repositories:

  • donraposo1-source/project-wolf
  • insidethemarginmedia-cpu/wolf-factory-home

Permissions requested: contents: read, metadata: read, checks: write, actions: write. Each token asks for only the subset its role needs.

The App must be public. GitHub only allows a private App to be installed on the account that owns it. Since this App must be installed on two personal accounts, "Any account" is required. It is still restricted by installation to the two repositories above, so being publicly installable does not grant access to anything.

Step 1 — Create the App

  1. Open https://github.com/settings/apps/new while signed in as insidethemarginmedia-cpu.
  2. Fill the form from the manifest below. If you prefer, the form on wolf-factory-automation.html is pre-filled — but it must be submitted from that signed-in session, so check the account first.
  3. Under Where can this GitHub App be installed? choose Any account.
  4. Create it. GitHub then shows the App ID and downloads a .pem private key.
{
  "name": "Wolf Factory Automation",
  "description": "Least-privilege CI authentication for the Wolf Factory bridge.",
  "url": "https://github.com/insidethemarginmedia-cpu/wolf-factory-home",
  "hook_attributes": {
    "active": false
  },
  "redirect_url": "https://github.com/insidethemarginmedia-cpu",
  "public": true,
  "default_permissions": {
    "contents": "read",
    "metadata": "read",
    "checks": "write",
    "actions": "write"
  },
  "default_events": [],
  "request_oauth_on_install": false,
  "setup_on_update": false,
  "repositories_hint": [
    "project-wolf",
    "wolf-factory-home"
  ],
  "owner": "insidethemarginmedia-cpu",
  "accountType": "user"
}

Step 2 — Install on both accounts

  1. Install on donraposo1-source: https://github.com/apps/wolf-factory-automation/installations/new
  2. If the install page opens an existing installation instead of a chooser, use the account chooser.
  3. Select Only select repositories → project-wolf. Never "All repositories".
  4. Repeat for insidethemarginmedia-cpu, selecting only wolf-factory-home.
"All repositories" on a personal account grants access to every repository that account owns. The run reports such an installation as over-scoped and refuses it.

Step 3 — Read the installation IDs

Open https://github.com/settings/installations and look at each Configure link. The number at the end is the installation ID:

https://github.com/settings/installations/<INSTALLATION_ID>

You need the Factory ID. The Home ID is useful for the audit but is not required.

Step 4 — Store the values

At Settings → Secrets and variables → Actions:

SecretValueNote
WOLF_FACTORY_APP_ID App settings page, "App ID" field Not a secret in the cryptographic sense, but never published either.
WOLF_FACTORY_APP_PRIVATE_KEY The .pem GitHub downloads when the App is created Paste the whole file including the BEGIN and END lines. This is the only value the agent must never see.
WOLF_FACTORY_READER_INSTALLATION_ID The installation URL for the Factory account Repeats the same ID as publisher and dispatcher, deliberately: one App, one installation per personal account.
WOLF_FACTORY_PUBLISHER_INSTALLATION_ID The installation URL for the Factory account Repeats the reader ID. This is expected, not a mistake.
WOLF_FACTORY_DISPATCHER_INSTALLATION_ID The installation URL for the Factory account Repeats the reader ID. This is expected, not a mistake.
Why the three installation IDs are equal. A GitHub App is installed once per account. One App on two personal accounts is two installations, so the three Factory roles share the Factory installation ID. The secrets have distinct names because each role is independent; the value repeats because there is only one installation to point at.

Then

Reply that the App is installed. The next run mints App tokens, publishes the private check through the App's own checks:write token — no status PAT needed — dispatches the Home workflow, and reports:

authentication.mode   = github-app
authRecovery.state    = VERIFIED
privateStatusCheck.state = PUBLISHED

The PAT and deploy-key fallbacks stay in place until that run is green.

If something goes wrong

  • APP_INSTALLATION_NOT_FOUND — the ID is from the other account.
  • APP_GRANT_DIFFERS — the App was created with different permissions; recheck Step 1.
  • OVER_SCOPED — the install used "All repositories"; reinstall with "Only select repositories".
  • APP_JWT_REJECTED — the key was truncated; re-paste the whole .pem including its BEGIN and END lines.
