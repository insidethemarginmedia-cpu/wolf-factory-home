### 3.2 What the tests actually verify

**`VERIFIED FACT`** — of 52 test files on the largest branch, **46 are CI

### 3.3 Integration debt

**`VERIFIED FACT`** — `main` carries **3 files** (2 workflows + README). The
largest branch carries **193 files / 26 204 insertions** relative to `main`.
Fourteen branches sit 197–289 commits ahead of their merge-base with `main`.

**`VERIFIED FACT`** — **4 open pull requests, 0 merged, 0 closed**, open since
2026-10-28. Their base branches are *other feature branches*, not `main`:
`work/omega-home-executor` → `arena/38f3a7f7`, `arena/156d9fee` → `arena/38f3a7f7`,
`arena/38f3a7f7` → `feat/public-runtime-probe`, `fix/omega-acceptance` →
`feat/public-runtime-probe`. Integration forms a chain that never reaches `main`.

**`EXPERIMENTALLY VALIDATED RESULT`** — pairwise `git merge-tree --write-tree`
over all 91 pairs of long-lived branches (≥50 commits ahead of merge-base):

- **48 of 91 pairs (52.7%) conflict**
- **115 conflicted file-paths in total**
- the two most common conflict files are `.github/workflows/night-shift-wakeup.yml`
  and `.github/workflows/private-controller-preflight.yml`

A control run on a synthetic repository (two branches editing disjoint files)
correctly reports 0 conflicts, and a synthetic pair editing one shared file
reports exactly 1 — confirming the measurement is not systematically inflated.
See `tests/wolf-research-instrument.test.mjs` tests 6–7.

> **Negative result preserved:** the instrument's first version reported
> *0 conflicts across all 91 pairs*. Cause: the `git()` helper re-threw errors
> as a new exception type that discarded `stdout`, where `merge-tree` prints
> conflict detail. This was a **false negative that would have understated
> integration debt to zero**. Fixed, regression-tested (test 6), and recorded
> here because a silent measurement failure is more dangerous than a wrong
> number that is visibly wrong.

### 3.4 Test-suite portability

**`EXPERIMENTALLY VALIDATED RESULT`** — controlled comparison of the same
504-test suite:

| condition | result |
|---|---|
| full clone with complete history | **504 pass, 0 fail**, 16.3 s |
| `git archive` export (no `.git`) | 492 pass, **2 fail** |
| fresh single-commit repo | 496 pass, **8 fail** |

Failures are tests that resolve pinned SHAs from repository history
(`PINNED_EXECUTOR_UNAVAILABLE`, "every reusable-workflow pin resolves to a real
commit"). **The suite is history-dependent**: it cannot run in a shallow or
exported workspace. Any CI design that checks out a single ref will produce
false failures.

**`SCIENTIFIC THEORY` (Theory of Constraints, Goldratt)** — improving any node
that is not the constraint does not increase system throughput. Under this map,
Factory-side optimisation has **zero** effect on time-to-product while
`project-wolf` read access remains denied.

**`HYPOTHESIS`** — the three `BLOCKED_EXTERNAL` items are a *single* Founder
intervention (one authorization change + one Supabase visibility grant + one
Vercel authorship mapping), not three independent projects. Falsifiable: if
restoring GitHub access does not also restore the other two, the hypothesis fails.

## 5. What this baseline does *not* establish

- **`ESTIMATE`** — no claim is made about lines of product code, product test
  coverage, or product defect rate: the private repository is unreadable.
- **`BLOCKED_EXTERNAL`** — no claim about Build Wolf PR #749: its repository
  identity is unresolved and must not be guessed from a PR number.
- **`VERIFIED FACT` (absence of evidence)** — Vercel deployment messages are
  *commit messages*, i.e. claims by their author. They are recorded as evidence
  that work occurred, **not** as independent verification that it works.
- No statistical inference is drawn from a single repository. Findings here are
  about *this* system.
